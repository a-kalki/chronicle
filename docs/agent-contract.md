# Контракт агента

Требования к адаптеру любого агента, который отправляет данные в chronicle. Новый агент считается подключённым, когда выполнены все пункты обязательного чек-листа.

## Поток `/finish`

```text
пользователь: /finish
  └─ адаптер (в агенте): запускает отсоединённый процесс и сразу отдаёт управление
       пользователь работает дальше / открывает новую сессию
  └─ фоновый процесс:
       1. неинтерактивный запуск агента на копии сессии
          с промптом prompts/extract.md и JSON Schema ExtractResult
       2. метки активности и ходы из лога сессии (с последнего watermark):
          реплики человека, пути в вызовах инструментов → проект хода
       3. коммиты автора за интервал сегмента из всех затронутых репо (общий хелпер chronicle)
       4. фокусы ходов из эпизодов выжимки
       5. сборка SessionReport v2 → chronicle report submit (через outbox)
       6. сохранение watermark
```

## Обязательные требования

| # | Требование | Детали |
|---|---|---|
| A1 | **Идентичность** | Адаптер знает имя агента, ID сессии, cwd и host (из конфига клиента) |
| A2 | **Неблокирующий `/finish`** | Отсоединённый процесс; пользователь не ждёт. Ошибка фона не теряет данные: пишется в лог и повторяется |
| A3 | **Выжимка самим агентом, дешёвой моделью** | Неинтерактивный запуск с контекстом сессии и общим промптом `prompts/extract.md` на **дешёвой** модели агента (Haiku, Flash и т.п.; задаётся в конфиге клиента `extractModel.<agent>`) — задача простая, дорогая модель не нужна. Ответ строго по JSON Schema `ExtractResult` (генерируется из `contract/`). Форк сессии, если агент умеет; иначе ход выжимки допустимо дописать в саму сессию |
| A4 | **Метки активности** | События `{ at, actor }` из лога сессии после watermark → `activitySource: 'log'`. Если лога нет — начало и конец сегмента → `activitySource: 'coarse'` |
| A5 | **Сегменты и watermark** | Каждый `/finish` — следующий `seq`. Watermark (позиция в логе) хранится локально у адаптера. Повторная отправка того же `seq` безопасна |
| A6 | **Доставка только через локальный клиент** | `chronicle report submit`. Ни прямых запросов к HTTP API, ни MCP для отчётов: только клиент гарантирует outbox |
| A7 | **Recall при неожиданной ошибке** | Скил или инструкция агента: при неожиданной ошибке или странном поведении инструмента — `chronicle search "<дословный текст ошибки>"` до попытки чинить |
| A8 | **Учёт пользы** | Основной путь — выжимка: агент видит в копии сессии свои `chronicle search`/`show` и перечисляет открытые записи в `ExtractResult.usage` (проверено вживую: Claude Code и pi — 6/6). В середине работы агент ничего не отмечает. `chronicle used` и MCP `knowledge_used` — для ручной отметки и агентов, работающих только через MCP. Сервер сам считает попадания в выдачу и открытия |
| A9 | **Только ловушки и факты** | Правила промпта выжимки адаптер не меняет: правила качества одни для всех агентов. Добавлять можно только данные — список ходов (A10) и брошенные ветки |
| A10 | **Ходы и пути** | Адаптер выделяет из лога ходы (реплика человека → до следующей реплики) и для каждого хода — пути из вызовов инструментов с видом действия (`edit`, `shell`, `read`). Проект хода считает общий хелпер chronicle (правила — `data-and-api.md` §2 Turn). Адаптер отдаёт ходы с действиями (`SessionRead.turns`); проекты, нумерацию и промпт делает общая часть `finish`: пронумерованный список реплик (`#3 14:05 «первые 200 символов»`) и недавние фокусы затронутых проектов (локальный кэш клиента — `finish` работает и без сети). Агент без лога — один ход на сегмент, проект запуска |

## ExtractResult v2 (что возвращает агент)

```ts
{
  work: {
    summary: string,                 // одна фраза о результате сегмента
    episodes: {
      from: number, to: number,      // диапазон номеров ходов из списка в промпте, включительно
      focus: string,                 // ≤ 60 символов; переиспользовать недавний, если подходит
      items: string[],               // результаты эпизода (Outcome)
    }[],                             // покрывают все ходы сегмента, не пересекаются
  },
  knowledge: {
    scope: 'project' | 'global',
    kind: 'trap' | 'fact',
    title: string,
    symptoms: string[],   // дословные тексты ошибок
    cause: string,
    fix: string,
    tags: string[],
  }[],
  usage: { entryId: string, helped: boolean | null }[],
}
```

Коммиты, файлы, метки активности, проекты ходов и идентичность адаптер добавляет сам — агенту их не доверяем. Ходы, не покрытые эпизодами, получают фокус соседнего эпизода; пересечения — побеждает более поздний эпизод.

## SessionReport v2 (что уходит в сервис)

```ts
{
  version: 2,
  replace?: true,                    // только chronicle replay
  session: { agent, id, host, seq, startedAt, endedAt },
  launch: { cwd: string, projectKey: string | null },
  projects: { key: string, remote?: string, name: string, path: string }[], // key — локальный в отчёте
  activity: { source: 'log' | 'coarse', events: { at, actor: 'user' | 'agent' }[] },
  turns: { idx: number, at: string, projectKey: string | null, focus: string | null }[],
  work: {
    summary: string,
    outcomes: { projectKey: string | null, focus: string | null, text: string }[],
    commits: { projectKey: string, hash, subject, at }[],
    files: { projectKey: string, path: string }[],
  },
  knowledge: KnowledgeCandidate[],
  usage: KnowledgeUsage[],
}
```

v1 сервис принимает и дальше (outbox старых клиентов): читается как сегмент без ходов с проектом из `project`.

## Чек-лист подключения нового агента

- [ ] Есть неинтерактивный режим с продолжением сессии (и, желательно, форком)
- [ ] Есть дешёвая модель для выжимки
- [ ] Есть вывод по JSON Schema (или надёжный JSON-вывод + валидация адаптером)
- [ ] Известно, где лежит лог сессии и как достать метки событий (иначе — `coarse`)
- [ ] Команда `/finish` (или аналог) запускает фон и не блокирует
- [ ] Инструкция recall (A7) подключена в глобальные правила агента
- [ ] Интеграционный тест адаптера на записанном фрагменте лога сессии

## Защита от рекурсии

Неинтерактивный запуск агента для выжимки сам завершается как сессия — и его хук завершения снова вызвал бы `chronicle finish`. Адаптер ставит дочернему процессу `CHRONICLE_EXTRACT=1`; при этой переменной `chronicle finish` ничего не делает.

## Ветвление сессий

Форк для выжимки видит только активную ветку сессии.

- **pi** (`/tree`): ветки, брошенные после watermark и не покрытые `branch_summary`, адаптер раскладывает в сжатый протокол (реплики, текст агента, правки и команды, ошибки инструментов; без чтения и служебных вызовов) и добавляет в промпт выжимки. Активное время считается по всем веткам.
- **Claude Code** (откат `Esc Esc`): не проверено — в реальных логах откатов пока не было. Если откат оставляет в логе ветки по `parentUuid`, нужна такая же раскладка, как у pi.
- **Новый агент** с ветвлением обязан обеспечить то же: брошенные ветки не должны выпадать из итога сессии.
