# chronicle — правила для агентов

Что это за сервис — [README.md](README.md). Здесь — где что лежит и куда что записывать.

## Начало сессии

1. Текущий этап и следующий пункт — [docs/plan.md](docs/plan.md).
2. Остальное читать по задаче, по карте ниже. Архив (`docs/archive/`) — только когда нужна история.

## Карта документов

| Документ | Что в нём | Что туда писать |
|---|---|---|
| [docs/plan.md](docs/plan.md) | текущий этап (чек-лист) и «Потом» | отметки о готовности, новые задачи этапа, отложенное |
| [docs/spec.md](docs/spec.md) | цели и не-цели, решения и **почему**, метрики, настройки, структура кода | новое архитектурное решение — строкой в таблицу §2 |
| [docs/data-and-api.md](docs/data-and-api.md) | объектная модель, процессы над данными, таблицы SQLite, HTTP API, MCP, CLI | любое изменение сущностей, таблиц, эндпоинтов, команд |
| [docs/agent-contract.md](docs/agent-contract.md) | требования к адаптеру агента, `ExtractResult`, `SessionReport`, статус агентов | изменения контракта и адаптеров |
| [docs/install.md](docs/install.md) | установка сервиса, клиента и агентов, ограничения, диагностика | новый шаг установки, новое ограничение |
| [docs/deploy.md](docs/deploy.md) | наш сервер: где что лежит, обновление, оговорки | изменения деплоя |
| [docs/archive/](docs/archive/) | закрытые этапы, разовые миграции | итог закрытого этапа, отработанные разделы |

Правила:
- **Живые документы описывают текущее состояние** (и цель текущего этапа с пометкой, например «v2»). Отработанное — в `docs/archive/` или просто удаляется: полная история в git.
- **Закрытие этапа:** итог в 2–3 строки с диапазоном коммитов → `docs/archive/stages.md`, чек-лист из `plan.md` удалить, пометки этапа в живых документах снять.
- **Не дублировать:** у каждого факта одно место; из других документов — ссылка.
- Ловушки окружения (симптом → причина → решение) — не в docs, а в базу chronicle (итог сессии делает это сам).

## Код

- Bun + TypeScript strict, Biome. Зависимости ядра — только `valibot` и `@valibot/to-json-schema`; новые — только по согласованию.
- TDD: сначала тест (`*.test.ts` рядом с кодом), потом реализация. Перед коммитом — `bun run check` (lint + typecheck + тесты).
- Слои: `src/domain` (чистые правила) ← `src/app` (use cases) ← `src/infra`, `src/http`, `src/cli`, `src/finish`, `src/adapters`. Контракт — `contract/` (valibot → JSON Schema).
- Комментарии и документация — по-русски. Коммиты — conventional commits по-русски: `feat(finish): …`, `fix(mcp): …`, `docs: …`.
- Деплой на сервер — `scripts/deploy.sh` по [docs/deploy.md](docs/deploy.md), только по просьбе пользователя.
