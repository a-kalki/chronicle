# chronicle

Сервис, который собирает итоги рабочих сессий с агентами (Claude Code, pi, agy) на любых машинах и отвечает на два вопроса о работе человека:

1. **Что сделано** — вклад для команды, результат для заказчика.
2. **Сколько работал** — вовлечённость для команды, основание оплаты для заказчика.

Попутно ведёт **базу ловушек**: ошибки окружения и инструментов (симптом → причина → решение), которые агенты находят по дословному тексту ошибки до того, как чинить.

## Что делает

- **Итог сессии без участия человека.** Сессия агента завершилась (`/clear`, выход, `/finish` в pi) — клиент в фоне делает выжимку дешёвой моделью самого агента, собирает коммиты и метки активности и отправляет отчёт. Человек не ждёт.
- **Хранит факты, а не готовые отчёты**: активность, ходы (реплика человека и работа агента до следующей), результаты, коммиты. Эпизоды, время и метрики вычисляются при чтении — отчётность можно строить потом, здесь или во внешнем сервисе.
- **Привязывает работу к проекту, где она шла**, а не к каталогу запуска: проект определяется у каждого хода по путям в вызовах инструментов, коммиты собираются из всех затронутых репозиториев.
- **Считает время без двойного счёта**: параллельные сессии не дают лишних часов — `5.6 ч (паралл. 1.1 ч)`.
- **Курирует знания на сервере**: агент присылает кандидатов, сервис через LLM сливает дубликаты, отсеивает лишнее, архивирует неиспользуемое и учитывает пользу.

## Как устроено

```text
машина (ноутбук, сервер, …)                         сервис chronicle (один на всех)

агент ── завершение сессии ──▶ chronicle finish      HTTP API /v1, MCP /mcp
  лог сессии → ходы, активность, проекты             SQLite
  выжимка: дешёвая модель агента на копии сессии     курирование знаний (LLM)
  коммиты автора из git                              эпизоды и время — при чтении
  → outbox ─────────────────── HTTPS ──────────────▶
chronicle search / show ◀──────────── знания ───────
```

Один сервис на всех людей и машины; на каждой машине — CLI-клиент `chronicle` с локальной очередью (отчёт не теряется без сети). Подробно — [Данные и API](docs/data-and-api.md).

## Запуск

Нужны Bun, git и Linux (подробности и ограничения — в инструкции).

```bash
git clone https://github.com/a-kalki/chronicle.git && cd chronicle
bun install && bun run check
```

1. **Сервис** — один на всех: `CHRONICLE_TOKENS=я:<токен> DEEPSEEK_API_KEY=<ключ> bun src/http/main.ts`.
2. **Клиент** на каждой машине: `bun run link` и `~/.config/chronicle/config.json`.
3. **Агенты**: хуки и скил recall.

Пошагово, со всеми настройками — **[docs/install.md](docs/install.md)**. Там же — [ограничения](docs/install.md#ограничения).
